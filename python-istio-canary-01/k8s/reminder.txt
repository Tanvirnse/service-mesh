To find a service account's principal identity (used in principals:):
# istioctl x authz check <pod-name> -n istio-test

It will return something like:
source principal: cluster.local/ns/istio-test/sa/python-app-sa

Locality Load Balancing is an important feature in Istio that helps optimize performance and availability in multi-region, multi-zone, or multi-cluster Kubernetes deployments.
Istio can use locality-aware routing to prefer service instances that are closer to the caller, typically in the same region or zone (based on cloud topology). This improves latency and reduces cross-region traffic costs.
